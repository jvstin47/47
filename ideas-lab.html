01 Building

Permission Layers in AI Interfaces

What if the user always knew exactly what the AI could see?

Most AI interfaces obscure context — what's in the prompt, what's remembered, what's inferred. I want to explore a visible "permission card" UI layer that surfaces this in real time, giving users genuine legibility over what they're interacting with.

What would make this real? A browser extension prototype for any chat UI, surfacing token context and system-prompt scope as a readable sidebar.

02 Thinking

Friction by Design

Removing all friction isn't always the right move.

Design dogma says eliminate friction. But some friction builds meaning — the delay before a letter arrives, the effort of a handwritten note. I'm collecting examples where designed friction improves the experience, not degrades it.

What would make this real? A written essay + a small annotated collection of friction-forward products that feel better for being slower.

03 Exploring

Context-Aware Reading Mode

The same content shouldn't look the same at 7am and 11pm.

Reading mode tools strip pages bare but ignore context entirely. What if reading mode was ambient-aware — typography density, contrast, and pacing adjusted to estimated cognitive state, time of day, and session length?

What would make this real? A Firefox extension with time-of-day reading profiles and a small study measuring retention across conditions.

04 Thinking

Micro-Portfolios for Specialists

What if your portfolio was one perfect page, not thirty average ones?

Generalist portfolios reward breadth. But specialists — a single-domain engineer, a focused writer, a niche researcher — need a different format. Depth over breadth. One case study that says everything, rather than a gallery that says nothing.

What would make this real? A template kit and a written framework for choosing what single project best represents you.

05 Exploring

The Offline-First Mental Model

Most apps pretend the internet always works. It doesn't.

Offline-first architecture is well understood technically. What's underexplored is the design language around it — how do you communicate sync state, conflict resolution, and uncertainty to a non-technical user without breaking their trust?

What would make this real? A design pattern library specifically for sync-state UI — status indicators, conflict modals, and latency-honest copy.

06 Dropped

Sound as Navigation Feedback

Could a subtle audio layer make interfaces feel more alive?

Explored using non-intrusive spatial audio cues — low-frequency tones, subtle clicks — to reinforce UI hierarchy and navigation depth. Dropped after testing: the overhead of audio permissions, accessibility conflict, and user habituation outweighed the benefit.

Why dropped? Accessibility requirements make opt-out audio patterns risky. The signal-to-noise problem wasn't solvable at low implementation cost.
